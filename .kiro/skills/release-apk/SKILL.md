# Release APK

Outage is distributed as a sideloaded APK (no Play Store). A release is: a version, a signed APK from EAS, a public direct link, the install page values, and a phone that proved it works.

Related: `/release` steering (`.kiro/steering/release.md`), install page spec (`.kiro/specs/web-and-area-pages` R7), brief Part J (submission checklist: direct APK link, video on a real device).

## Rules

- **Ask the human before:** the first EAS build (uses their Expo account and one of a small monthly allowance), publishing a release, and deploying the Worker with a new APK link.
- **Never commit** an APK, a keystore, `google-services.json`, an `.env` file or a token. The guard hooks block it; do not look for ways around them. Secrets live in EAS environment variables and Wrangler secrets.
- **Do not spend a build** on a docs-only change, or before preflight is green.
- The signing key must be the same for every release, or phones cannot update. Never let a second key be generated by accident.

## Steps

1. **Preflight.** `node .kiro/skills/release-apk/scripts/preflight.mjs` (add `--profile preview` for a field build). It checks branch, clean and pushed tree, `expo.version` against the last tag, the EAS profile builds an APK with auto-increment and no inline secrets, no secret file tracked, `.gitignore`, `.kiro` tracked, last test result, and the OEM guide status (a warning for unverified makers). Fix every FAIL.
2. **Version.** Bump `expo.version` in `apps/mobile/app.json` (MAJOR.MINOR.PATCH). With `cli.appVersionSource: remote` EAS raises `android.versionCode` itself (https://docs.expo.dev/build-reference/app-versions/). Commit: `chore(release): vX.Y.Z [spec:none task:release]`.
3. **Ask the human** to confirm: version, profile, and that a build may be spent. Say how many builds the free plan allows (30 a month at the last check, https://expo.dev/changelog/2023-08-01-eas-free-plan-limits; confirm on https://expo.dev/pricing).
4. **Build.** From `apps/mobile`: `npx eas-cli build --platform android --profile production --non-interactive --no-wait --json` (confirm flags with `eas build --help`). Free-plan builds queue at lower priority and can wait for hours. Poll `npx eas-cli build:list --platform android --limit 1 --json --non-interactive`. Do not start a second build while one is queued.
   - The first build for the project needs the human to run it once interactively so EAS creates the keystore. After that, ask them to download a backup of the credentials (`eas credentials`) and keep it outside the repository.
5. **Download** the artifact URL from the build, to a temp folder outside the repository.
6. **Inspect.** `node .kiro/skills/release-apk/scripts/apk-info.mjs <file.apk> --version X.Y.Z --url <final link> --json`. It reads the package, prints size and SHA-256, and fails for a file that is not a signed APK. It cannot prove the signature is valid or whose key it is; if `apksigner` is installed, also run `apksigner verify --print-certs <file.apk>` and compare the certificate digest with the previous release.
7. **Publish a draft release** with the GitHub REST API (`references/github-release.md`), upload the APK as an asset, and keep it a draft until the smoke test passes. The direct link is `https://github.com/<owner>/<repo>/releases/download/vX.Y.Z/outage-X.Y.Z.apk`.
8. **Smoke test on a real phone** (`references/smoke-test.md`). A release that has not been installed from the final link is not released.
9. **Publish** the release (not a draft) and set the install page values: `APK_URL`, `APK_VERSION`, `APK_SIZE_BYTES`, `APK_SHA256` in `workers/api/wrangler.toml` `[vars]` (the output of `apk-info`). Ask the human before `wrangler deploy`. Open `/install` and check the link, size and checksum.
10. **Record.** `docs/kiro-log.md` entry (version, build id, checksum, phone used, result), `docs/status.md`, and tag `vX.Y.Z` on the released commit. Update the README download link.

## If something fails

| Problem | Do |
|---|---|
| Build fails | Read the build logs with `eas build:view`; fix in a normal commit. Do not retry blindly: each build counts. |
| EAS built an `.aab` | The profile lacks `android.buildType: "apk"` (https://docs.expo.dev/build-reference/apk/). Fix `eas.json`; preflight catches it. |
| "App not installed" on the phone | Same package with a different signing key, or a lower `versionCode`. Uninstall the old app only if the human agrees, and note the cause. |
| Phone says the file is unsafe | Normal for sideloaded apps; the install page explains how to allow it. |
| Smoke test fails | Do not publish. Open a Bugfix Spec with the observed behavior, and say so to the human. |
| Checksum differs after download | Stop. Re-download. If it still differs, do not publish. |
